ไปหน้าเข้าสู่ระบบ
ถ้าต้องการใช้งานเว็บอย่างเดียว หยุดตรงนี้ได้เลยไม่ต้องเปิด Swagger หรือคัดลอก token เพื่ออ่านสูตรบนเว็บ

กดดูสูตรหนึ่งครั้ง
ข้อมูลเดินทางอย่างไร?

API คือทางเชื่อมระหว่างหน้าจอเว็บกับเซิร์ฟเวอร์ ไม่ใช่อีกหน้าที่ผู้ใช้ต้องเปิด

กดแต่ละขั้นเพื่อดูว่าใครทำอะไร ภาพนี้อธิบายการทำงาน ไม่ได้ส่งคำขอจริง

  1. 1 คุณเลือกสูตรบนเว็บ

    หน้าเว็บส่งคำขออ่านสูตรไปที่ API พร้อมรหัสสูตรที่เลือก

    เหมือนบอกครัวว่า “ขอดูสูตรจานนี้”

  2. 2 API ค้นข้อมูลให้

    เซิร์ฟเวอร์ตรวจรหัสสูตร แล้วอ่านสูตรและวัตถุดิบจากฐานข้อมูล หากไม่พบ จะตอบกลับว่าไม่พบสูตร

    API เป็นคนรับคำขอ · MySQL เป็นที่เก็บข้อมูล

  3. 3 เว็บจัดข้อมูลให้อ่าน

    API ส่งชื่อสูตร วิธีทำ และวัตถุดิบกลับมาเป็นข้อมูล เว็บจึงจัดเป็นหน้ารายละเอียดที่คุณเห็น

    รูปแบบข้อมูลเรียกว่า JSON ไม่ใช่ภาพหน้าเว็บ

แล้วตอนเพิ่มสูตรหรือให้คะแนน ต่างกันอย่างไร?

การอ่านสูตรไม่ต้องมีบัญชี แต่การบันทึกต้องส่งหลักฐานการเข้าสู่ระบบไปด้วย เซิร์ฟเวอร์ตรวจบทบาทและเจ้าของสูตรก่อนเขียนลงฐานข้อมูล การซ่อนปุ่มบนหน้าเว็บอย่างเดียวไม่ใช่การป้องกันสิทธิ์

ดูเส้นทางบันทึกและตรวจผล

ตอนนำเสนอ อธิบายตามภาพจากซ้ายไปขวาได้เลย
หน้าเว็บรับการใช้งาน · API จัดการคำขอ · MySQL เป็นฐานข้อมูลหลัก

ลองอ่านข้อมูลผ่าน API
ระบบนี้เก็บข้อมูลที่ไหน?

แอปใช้ MySQL เป็นฐานข้อมูลหลัก โหมดทดสอบอาจใช้ข้อมูลในหน่วยความจำซึ่งไม่คงอยู่หลังเริ่มระบบใหม่ ดูการตั้งค่าของระบบนี้ ข้อมูลนี้ไม่ใช่ผลตรวจสุขภาพฐานข้อมูล

01 / อ่านข้อมูล

ดูสูตรก่อน โดยไม่แก้ข้อมูล

คำสั่ง GET ใช้อ่านข้อมูล ขั้นนี้ไม่ต้องเข้าสู่ระบบ

  1. เปิดคำสั่ง GET /api/v1/recipes ใน Swagger
  2. กด Try it out แล้วกด Execute
  3. ดูรหัส 200 และรายการสูตรใน data

data คือข้อมูลที่ได้กลับมา ส่วน pagination บอกจำนวนสูตรและหน้าที่กำลังอ่าน

02 / เข้าสู่ระบบ

ยืนยันบัญชีก่อนส่งข้อมูล

บัญชีบนหน้าเว็บกับ Swagger เข้าสู่ระบบแยกกัน

  1. เปิด POST /api/v1/auth/login แล้วกด Try it out
  2. ใส่บัญชีของคุณตามตัวอย่างด้านล่าง แล้วกด Execute
  3. เมื่อได้รหัส 200 คัดลอกค่าจาก data.token
  4. กด Authorize ด้านบน วางเฉพาะค่า token ไม่ต้องใส่คำว่า Bearer หรือเครื่องหมายคำพูด แล้วกด Authorize และ Close
ดูรูปแบบข้อมูลเข้าสู่ระบบ
{ "username": "USERNAME", "password": "PASSWORD" }

แทน USERNAME และ PASSWORD ด้วยบัญชีที่ได้รับสำหรับโครงงาน อย่าเผยแพร่รหัสผ่านหรือ token

Token มีอายุ 15 นาที ถ้าหมดอายุให้เข้าสู่ระบบใหม่ การเข้าสู่ระบบบนหน้าเว็บไม่ได้ทำให้ Swagger เข้าสู่ระบบตาม

03 / ส่งข้อมูล

บันทึกได้ ตามสิทธิ์ของบัญชี

POST ใช้ส่งข้อมูล ส่วน DELETE ใช้ลบข้อมูล

ระวัง นี่คือข้อมูลจริงบนเว็บ

เมื่อเพิ่มสูตร เพิ่มวัตถุดิบ ให้คะแนน หรือลบสูตร ปุ่ม Execute จะบันทึกหรือลบข้อมูลจริง ใช้เฉพาะสูตรทดสอบของคุณ หากยังไม่พร้อมให้ทดลอง GET ต่อได้

เลือกสิ่งที่บัญชีของคุณทำได้

  • อ่านสูตรทุกคน ไม่ต้องเข้าสู่ระบบ
  • ให้คะแนนสมาชิกทุกบทบาท ครั้งเดียวต่อบัญชีต่อสูตร
  • สร้างสูตรบัญชี chef หรือ admin
  • เพิ่มวัตถุดิบ หรือลบสูตรchef ที่เป็นเจ้าของสูตร หรือ admin

เริ่มจากสูตรทดสอบของคุณ

หลัง Authorize เลือก POST /api/v1/recipes ใช้ตัวอย่างเมื่อพร้อมบันทึกเท่านั้น

ดูตัวอย่างข้อมูลสร้างสูตร
{
  "name": "ไข่เจียวทดสอบ",
  "categoryId": 1,
  "instructions": "ตีไข่แล้วทอดให้สุก",
  "cookTimeMinutes": 8,
  "difficulty": "easy"
}

ไม่ต้องส่ง authorId ระบบใช้บัญชีที่เข้าสู่ระบบเป็นผู้เขียน รหัส 201 คือสร้างสำเร็จ เก็บ data.id ไว้ใช้เปิดสูตรนั้น

ดูตัวอย่างให้คะแนน และเพิ่มวัตถุดิบ

ให้คะแนนผ่าน POST /api/v1/recipes/{id}/ratings โดยแทน {id} ด้วยรหัสสูตร

{ "ratingScore": 5, "reviewComment": "ทำตามได้ง่าย" }

เจ้าของสูตรที่เป็น chef หรือ admin เพิ่มวัตถุดิบผ่าน POST /api/v1/recipes/{id}/ingredients ตัวอย่างนี้ใช้ไข่ไก่รหัส 5 จากชุดข้อมูลตั้งต้น ดูรหัสปัจจุบันได้จาก GET /api/v1/ingredients

{ "ingredientId": 5, "quantity": 2, "unit": "ฟอง" }

การลบสูตรจะลบวัตถุดิบที่ผูกกับสูตรและรีวิวของสูตรนั้นด้วย

เปิดคำสั่งสร้างสูตร ↗
ดูคำสั่งทั้งหมด 12 รายการสำหรับค้นหาคำสั่งและเปิดรายละเอียดใน Swagger

API ทำอะไรได้บ้าง?

มี 12 คำสั่ง แยกตามสิ่งที่ต้องการทำ กดชื่อคำสั่งเพื่อดูฟิลด์และตัวอย่างฉบับเต็มใน Swagger

อ่านสูตร หมวดหมู่ และวัตถุดิบ · ไม่ต้องเข้าสู่ระบบ
  • ดูรายการสูตร ค้นหา กรอง และเรียงลำดับGET/api/v1/recipes
  • ดูรายละเอียดและวัตถุดิบของสูตรGET/api/v1/recipes/{id}
  • ดูหมวดหมู่อาหารและรหัสหมวดหมู่GET/api/v1/categories
  • ดูวัตถุดิบที่มีในคลังและรหัสวัตถุดิบGET/api/v1/ingredients
สร้างสูตร เพิ่มวัตถุดิบ และลบสูตร · ต้องเข้าสู่ระบบ
  • สร้างสูตรอาหารใหม่บัญชี chef หรือ adminPOST/api/v1/recipes
  • เพิ่มวัตถุดิบลงในสูตรchef ที่เป็นเจ้าของสูตร หรือ admin · วัตถุดิบซ้ำในสูตรเดียวไม่ได้POST/api/v1/recipes/{id}/ingredients
  • ลบสูตร รวมถึงวัตถุดิบที่ผูกกับสูตรและรีวิวchef ที่เป็นเจ้าของสูตร หรือ admin · ลบแล้วเรียกคืนจาก API ไม่ได้DELETE/api/v1/recipes/{id}
ดูรีวิวและให้คะแนน
  • ดูรีวิว จำนวนคะแนน และคะแนนเฉลี่ยไม่ต้องเข้าสู่ระบบGET/api/v1/recipes/{id}/ratings
  • ให้คะแนน 1–5 และเขียนรีวิวสมาชิกที่เข้าสู่ระบบทุกบทบาท · ครั้งเดียวต่อสูตรPOST/api/v1/recipes/{id}/ratings
เข้าสู่ระบบ หาไอเดียเมนู และดูข้อมูลระบบ
  • เข้าสู่ระบบเพื่อรับ tokenใช้ชื่อผู้ใช้และรหัสผ่าน ไม่ต้องมี token ก่อนPOST/api/v1/auth/login
  • หาเมนูจากวัตถุดิบภาษาอังกฤษ เช่น chicken_breastไม่ต้องเข้าสู่ระบบ · ใช้บริการ TheMealDB หากบริการขัดข้องจะแจ้งและส่งรายการสำรองGET/api/v1/external/meal-ideas
  • ดูโหมดจัดเก็บข้อมูลและส่วนประกอบของระบบไม่ต้องเข้าสู่ระบบ · เป็นข้อมูลการตั้งค่า ไม่ใช่ผลตรวจฐานข้อมูลGET/api/v1/system

ข้อมูลที่ส่งเข้ามาใช้ชื่อฟิลด์ เช่น cookTimeMinutes แต่ข้อมูลสูตรที่อ่านกลับมาใช้ cook_time_minutes ให้ดูชื่อฟิลด์ของแต่ละคำสั่งใน Swagger หรือ ไฟล์ OpenAPI ซึ่งเป็นเอกสารอ้างอิงหลัก

อ่านรหัสตอบกลับอย่างไร?เมื่อสำเร็จ หรือเมื่อคำขอไม่ผ่าน

ได้ผลลัพธ์แบบนี้ ต้องทำอย่างไร?

ดูรหัสในส่วน Server response ก่อน ถ้าไม่สำเร็จ ให้อ่านข้อความใน error.message เพิ่มเติม

200
สำเร็จ อ่านข้อมูลหรือเข้าสู่ระบบได้แล้ว
201
บันทึกสำเร็จ ข้อมูลใหม่ถูกสร้างแล้ว
400
ข้อมูลไม่ถูกต้อง ตรวจฟิลด์ที่จำเป็น ชนิดข้อมูล และค่าที่อนุญาต
401
ยังไม่เข้าสู่ระบบ รหัสผ่านผิด หรือ token หมดอายุ ให้เข้าสู่ระบบใหม่
403
เข้าสู่ระบบแล้วแต่ไม่มีสิทธิ์ เช่น ใช้บัญชีสมาชิกเพิ่มสูตร หรือแก้สูตรของคนอื่น
404
ไม่พบข้อมูล ตรวจรหัสสูตรหรือรหัสวัตถุดิบที่ส่งไป
409
ข้อมูลซ้ำ เช่น เคยให้คะแนนสูตรนี้แล้ว หรือเพิ่มวัตถุดิบเดิมในสูตร
429
ส่งคำขอถี่เกินไป รอสักครู่แล้วลองใหม่ ไม่ต้องกดซ้ำ
